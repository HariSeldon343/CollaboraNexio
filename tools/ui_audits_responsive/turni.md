## Findings

### F1 — Coachmark popover ("1) Tipi Turno") covers half the calendar at 375px and pushes a horizontal scrollbar
- **Severity:** critical
- **Breakpoint:** 375px (also 768px but less severe)
- **Selector / element:** `.turni-tour-box` and `.turni-tour-overlay` (file: `assets/css/shifts.css:783-806`); generated by `assets/js/shifts.js:299-374`.
- **Screenshot region:** Mobile — entire upper half of the screen is occluded by the white card "1) Tipi Turno / Qui crei/modifichi i tipi (orari, colore, icona) ..." with Indietro/Avanti/Non mostrare più buttons.
- **Current behaviour:** `.turni-tour-box { position: fixed; width: min(420px, calc(100vw - 32px)) }` ⇒ on 375px viewport width = `min(420, 343) = 343px` (fine for width). However the JS positions the box ABSOLUTELY based on the highlighted target (`#shiftTypesBtn`), which on mobile collapses into the wrapped header so the box ends up roughly y=180px overlapping the calendar weekdays. There's no mobile-specific positioning fallback — at narrow widths the popover should "anchor bottom" or "fullscreen sheet" pattern.
- **Root cause (CSS):** Tour overlay positioning is JS-driven (lines 299-374) using `getBoundingClientRect()` of the target. On mobile the target button is hidden in the wrapped/overflowing header (see F2), so the rect math is undefined or returns a clipped value; the box lands on top of the calendar.
- **Recommended fix:** Add mobile-anchored fallback as bottom sheet. CSS-only piece:
```css
@media (max-width: 768px) {
    .turni-tour-box {
        /* Force bottom-sheet on mobile, ignore JS-computed top/left */
        position: fixed !important;
        left: 12px !important;
        right: 12px !important;
        top: auto !important;
        bottom: 16px !important;
        width: auto !important;
        max-width: none !important;
        max-height: 60vh;
        overflow-y: auto;
    }
    .turni-tour-highlight {
        /* On mobile the target is offscreen; hide the cutout */
        display: none;
    }
}
```
Also requires JS update to skip the rect math on `matchMedia('(max-width: 768px)')` — flag as **REQUIRES JS CHANGE** to fully fix.

### F2 — Header toolbar overflows even at 768px (Settimana / Mese / Azienda / Guida rapida / Riepilogo / Tipi Turno / Wizard / Bilanciamento / Nuovo Turno / Seleziona / Elimina)
- **Severity:** critical
- **Breakpoint:** both (375px completely unusable; 768px shows only first 4 controls)
- **Selector / element:** `.main-content > .header > .flex.items-center.gap-4` (file: `turni.php:94-170`)
- **Screenshot region:** Tablet — only "Settimana / Mese / Azienda: Tutte le aziende / Guida rapida / Riepilogo / Tipi Turno" visible; "Wizard Turni / Bilanciamento / Nuovo Turno / Seleziona / Elimina selezionati / Benvenuto" all clipped right edge. Mobile — only "Settimana / Mese / Azienda" visible above the fold.
- **Current behaviour:** Up to 8 buttons (admin/manager view) + "Benvenuto" greeting all share a single flex row. components.css `.header > .header-right` rule (lines 82-92) provides `flex-wrap: wrap` on the OUTER header but the INNER `.flex.items-center.gap-4` (turni.php line 96) is its own flex container WITHOUT wrap — so its children overflow horizontally.
- **Root cause (CSS):** Tailwind-style utility `.flex.items-center.gap-4` from styles.css doesn't include `flex-wrap`. The header has 9-12 controls (depending on permissions) and at 768px the cumulative width is ~1100px.
- **Recommended fix:**
```css
@media (max-width: 1280px) {
    .main-content > .header > .flex.items-center {
        flex-wrap: wrap;
        gap: 8px;
        row-gap: 8px;
        justify-content: flex-start;
    }
}
@media (max-width: 768px) {
    /* Drop the verbose "Benvenuto, ..." on phones to save the row */
    .main-content > .header > .flex.items-center > .text-sm.text-muted {
        display: none;
    }
    /* Make every header button compact */
    .main-content > .header .btn,
    .main-content > .header .btn-sm,
    .main-content > .header .btn-outline,
    .main-content > .header .btn-secondary,
    .main-content > .header .btn-primary,
    .main-content > .header .btn-danger {
        font-size: 12px;
        padding: 6px 10px;
        min-height: 36px;
    }
    /* SVG icons take less space */
    .main-content > .header .btn svg {
        width: 14px;
        height: 14px;
    }
}
@media (max-width: 480px) {
    /* Stack view-selector full-width row 1 */
    .main-content > .header .shifts-view-selector {
        width: 100%;
    }
}
```

### F3 — Month-view 7-column grid produces 50px cells at 375px (date numbers + any badge unreadable)
- **Severity:** critical
- **Breakpoint:** 375px
- **Selector / element:** `.shifts-month-grid` and `.shifts-month-cell` (file: `assets/css/shifts.css:442-475`)
- **Screenshot region:** Mobile — month grid fills the rest of the page with very narrow columns ~46px wide (375 - 24 page padding - 14 cell paddings = ~337/7 ≈ 48px). Date numbers (1-31) sit alone in cells. The "Maria · Asseenza" badge in the May 1st cell is truncated.
- **Current behaviour:** `.shifts-month-grid { display: grid; grid-template-columns: repeat(7, 1fr); }` enforces 7 equal columns regardless of viewport. Combined with `.shifts-month-cell { min-height: 100px; padding: var(--space-2); }` (8px padding eats into the already-tiny 48px cell width).
- **Root cause (CSS):** No mobile responsive rule for month grid; the existing `@media (max-width: 768px)` (shifts.css:1538) only addresses the WEEK-view grid (`.shifts-grid-header`, `.shifts-row`) — month-grid is never narrowed.
- **Recommended fix:** **REQUIRES MARKUP CHANGE for ideal solution** (replace 7-col grid with a stacked agenda list on mobile), but a CSS-only mitigation:
```css
@media (max-width: 768px) {
    .shifts-calendar-wrapper {
        overflow-x: auto;
        padding: var(--space-2);
    }
    .shifts-month-grid,
    .shifts-month-header {
        min-width: 700px; /* horizontal scroll instead of cramped cells */
    }
    .shifts-month-cell {
        min-height: 80px;
        padding: 4px;
    }
    .month-cell-date {
        font-size: 12px;
    }
}
@media (max-width: 480px) {
    .shifts-month-grid,
    .shifts-month-header {
        min-width: 560px; /* still scrolls horizontally but readable */
    }
}
```
Add a visible scroll-hint: `.shifts-calendar-wrapper { background: linear-gradient(...) }` to indicate horizontal scroll is possible.

### F4 — `.shifts-layout` `height: calc(100vh - var(--header-height) - var(--space-12))` produces incorrect height on mobile because header wraps to 3 rows
- **Severity:** critical
- **Breakpoint:** both
- **Selector / element:** `.shifts-layout` (file: `assets/css/shifts.css:11-16`)
- **Screenshot region:** Both — the calendar visibly fights for vertical space, requesting more than available, leading to inner scrollbars.
- **Current behaviour:** `height: calc(100vh - var(--header-height) - var(--space-12))` assumes `--header-height` is 64px (constant). But the header on turni.php WRAPS at 1024px and below to 2-3 rows (~140-200px tall), so the calculated height is ~180px taller than the available space → layout overflows downward.
- **Root cause (CSS):** Hardcoded `--header-height` in the calc; no `auto` fallback for wrapped-header pages.
- **Recommended fix:**
```css
@media (max-width: 1024px) {
    .shifts-layout {
        flex-direction: column;
        height: auto !important;
        min-height: calc(100vh - 200px);
    }
}
```
The existing rule at shifts.css:1518-1521 already does `flex-direction: column; height: auto;` at <=1024px, but it's missing `!important` and the calculated height earlier in the cascade may still apply due to specificity.

### F5 — Page header wraps but inner `.flex.items-center.gap-4` does not (same root issue as ticket.php F4 but more severe due to 8-12 children)
- **Severity:** critical


### F6 — `.shifts-view-selector` (Settimana / Mese pill group) becomes 100% width at 768px but its buttons retain text + icon causing button wrap inside the pill

### F7 — Requests sidebar (`<aside class="shifts-requests-sidebar">`) collapses to top at 1024px with `max-height: 300px` but stacks BELOW the calendar instead of being a collapsible panel
- **Severity:** major
- **Breakpoint:** 1024px and below
- **Selector / element:** `.shifts-requests-sidebar` (file: `assets/css/shifts.css:1517-1535`); markup `turni.php:212-236`
- **Screenshot region:** Tablet — bottom shows "Richieste" header at the very bottom; the sidebar moved below calendar correctly per the existing rule but its 300px tall block forces the calendar above to be smaller.
- **Current behaviour:** `@media (max-width: 1024px) { .shifts-layout { flex-direction: column } .shifts-requests-sidebar { width: 100%; max-height: 300px } }`. This is OK at 768px but at 375px the sidebar wastes 300px of vertical space when there are zero requests.
- **Root cause (CSS):** No collapsed state for the sidebar on mobile; always shown at 300px even when empty.
- **Recommended fix:**
```css
@media (max-width: 768px) {
    .shifts-requests-sidebar {
        max-height: none;
        order: 99; /* always last */
    }
    /* Empty state shouldn't dominate */
    .shifts-requests-sidebar:has(.requests-empty) {
        max-height: 140px;
    }
    .requests-empty svg {
        width: 32px;
        height: 32px;
    }
    .requests-empty p {
        font-size: 12px;
    }
}
```
Better solution: **REQUIRES MARKUP CHANGE** to add a `<details>` wrapper or a collapse toggle.

### F10 — `.shifts-current-period` (e.g. "Maggio 2026") at 375px sits inline with prev/next nav buttons creating cramped row
- **Severity:** major
- **Breakpoint:** 375px (rule exists at <=480px but partially insufficient)
- **Selector / element:** `.shifts-current-period` (file: `assets/css/shifts.css:121-126`; mobile rule 1582-1591)
- **Screenshot region:** Mobile — at 375 the title "Maggio 2026" is centered under prev/today/next based on the existing 480px rule (`width: 100%; order: -1`), which is fine. BUT at 375 the `text-align: center` puts it on its own row. Verify by looking at the actual screenshot: in the mobile shot the period title isn't visible (coachmark obscures). At tablet (768) the whole `.shifts-calendar-header` shows "Maggio 2026" centered with nav buttons left and "Tipi turno (1)" pill right — this is OK.
- **Current behaviour:** Existing `@media (max-width: 480px)` rule already handles this: `.shifts-current-period { width: 100%; text-align: center; order: -1 }`. So the issue is only that the rule fires below 480px (i.e. NOT at 481-767px range).
- **Root cause (CSS):** Breakpoint mismatch: `.shifts-calendar-header { flex-wrap: wrap; gap: var(--space-3) }` only kicks in at <=1024px; period title only stretches to full width at <=480px. Between 481-1023px the title sits centered with nav left and "Tipi turno" right, which works *visually* but cramps if labels grow.
- **Recommended fix:**
```css
@media (max-width: 768px) {
    .shifts-current-period {
        font-size: var(--text-base);
        flex: 1 1 100%;
        text-align: center;
        order: -1;
    }
    .shifts-calendar-header {
        gap: var(--space-2);
    }
}
```

## Cross-page note

Both `ticket.php` and `turni.php` share the same root issue with the page-header inner row using bare Tailwind-style `.flex.items-center.gap-4` without `flex-wrap`. A single global rule in `components.css` would fix it everywhere:

```css
/* Add to assets/css/components.css under "PER-PAGE HEADER" section */
@media (max-width: 1024px) {
    .main-content > .header > .flex,
    .main-content > header.header > .flex {
        flex-wrap: wrap;
        gap: 8px;
    }
}
```

This would resolve F4/ticket.md and F2+F5/turni.md in one shot. Recommend prioritising this systemic fix over per-page selectors.
